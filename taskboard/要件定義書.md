# トレロ風タスク管理アプリ 要件定義書

## 概要
シンプルなトレロ風タスク管理アプリ。個人利用を想定する。
自分のPCで Spring Boot のサーバーを起動し、ブラウザから使う。

## 背景・方針
機能は必要なものに絞る。既存の高機能版とは別物として、基本機能(カードの追加・削除・移動)に加え、期限・優先度・カテゴリの設定、並び替え、カードの色設定までを実装する。

## 利用者像
視力の弱いユーザーでも使いやすいよう、大きめの文字サイズ・高コントラストな配色をデフォルトで採用する(アクセシビリティを最初から考慮する)。
期限切れ・優先度・カードの色などは**色だけに頼らず、必ず文字でも表示する**。

## 機能要件(スコープ内)
1. 固定3カラム: 「未着手」「進行中」「完了」
2. タスクカードの追加(テキスト入力)
3. タスクカードの削除
4. タスクカードをドラッグ&ドロップでカラム間移動
5. ブラウザを閉じてもデータが残るよう、データベース(Docker で動かす PostgreSQL)に保存
6. 大きめの文字サイズ・高コントラストな配色をデフォルトのスタイルとする
7. カードの編集: 追加後のカードの内容・期限・優先度・カテゴリ・色を編集画面で変更できる
8. 期限の設定: カードごとに日付を指定できる(未設定も可)
   - 期限切れ・今日が期限のカードは「期限切れ」「今日まで」と文字で表示する
9. 優先度の設定: 「高」「中」「低」の3段階から選ぶ。カード上に文字ラベルで表示する
10. カテゴリの設定: カードごとに自由に文字で入力できる(未設定も可)。カード上に文字で表示する
11. カードの色設定: 用意した数色から選ぶ
    - 選択肢には色名も文字で表示する
    - どの色でもカードの文字がはっきり読めるコントラストを保つ
12. 並び替え: 各カラムの上部で、カラムごとに個別に並び順を選べる
    - 選択肢: 「手動(ドラッグ順)」「期限が近い順」「優先度が高い順」「カテゴリ順(名前順)」
    - 期限なし・カテゴリなしのカードは末尾に表示する
    - 選んだ並び順もサーバーに保存する

## 非機能要件
- ユーザー認証なし
- 複数人での共有なし(自分のPC上でのみ利用)
- レスポンシブ対応は必須としない(PCブラウザでの利用を想定)

## 今回のスコープ外(将来の拡張候補)
テーマ切替、文字サイズ切替、カラムの追加・編集・削除、カテゴリ一覧の管理(追加・編集・削除)、ログイン機能、インターネット上への公開 など。
必要になれば既存の高機能版を参考にできる。

## 画面構成(簡易)
- ヘッダー(タイトル)
- 3カラムのボード(各カラムの上部に並び替えメニュー)
- カード編集画面(ダイアログ): 内容・期限・優先度・カテゴリ・色を設定

## 技術スタック

### 全体の構成図
```
[ブラウザ]
  React で作った画面(フロントエンド / 入口は tasksboard.html)
        │  fetch で JSON をやり取り(REST API)
        ▼
[Spring Boot サーバー](バックエンド / http://localhost:8080)
  Controller(API の窓口)→ Service(処理)→ Repository(DB操作)
        │  Spring Data JPA(localhost:5432 に接続)
        ▼
[PostgreSQL データベース](Docker のコンテナ「taskboard-db」で動く)
  データは Docker のボリューム「taskboard-db-data」に保存
```

開発中と完成後で、画面の配信元が変わる。
- **開発中**: React の開発サーバー(Vite / `http://localhost:5173`)が画面を配信し、`/api` へのアクセスを Spring Boot(8080)に中継する
- **完成後**: `npm run build` で React の画面を HTML/JS/CSS に変換して `src/main/resources/static/` に出力し、Spring Boot が画面も API もまとめて配信する

### フロントエンド
- ライブラリ: React 19
- 開発ツール: Vite 8(開発サーバーとビルド)/ Node.js・npm
- 言語: JavaScript(JSX)。TypeScript は使わない
- 置き場所: `taskboard/frontend/`
- 入口の HTML: `frontend/tasksboard.html`(`index.html` ではなくこの名前を使う)
- 部品(コンポーネント)構成:

```
App(アプリ全体: ヘッダー・お知らせ・読み込み・ドラッグ中のカードの管理)
 ├─ Board(ボード)
 │   └─ Column × 3(未着手・進行中・完了。並び替えメニュー・カード追加ボタン・ドロップ先)
 │       └─ TaskCard × 件数分(編集・削除・上へ・下へボタン、ドラッグ元)
 ├─ TaskDialog(カードの追加・編集画面)
 └─ DeleteDialog(削除の確認画面)
     ※ TaskDialog と DeleteDialog は、共通の Modal(ブラウザ標準の dialog)を使う
```

- サーバーとの通信: fetch で REST API を呼ぶ
- スタイル: CSS(大きめの文字サイズ・高コントラストな配色をデフォルトで組み込む)
- 対応ブラウザ: 主要モダンブラウザ(Chrome/Edge等)を想定

### バックエンド
- 言語: Java 21(Microsoft Build of OpenJDK)
- フレームワーク: Spring Boot 4.1
  - Spring Web … REST API と画面ファイルの配信
  - Spring Data JPA … データベース操作
  - Bean Validation(Hibernate Validator)… 入力チェック
- ビルドツール: Maven(プロジェクト同梱の Maven Wrapper `mvnw` を使うため、Maven 本体のインストールは不要)
- 接続設定: `src/main/resources/application.properties`(接続先・ユーザー名・パスワードは環境変数 `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` で上書きできる)

### データベース
- 種類: PostgreSQL 18
- 動かし方: Docker Desktop 上のコンテナとして動かす(設定ファイルは `taskboard/compose.yaml`)
- コンテナ名: `taskboard-db`
- 接続先: `localhost:5432`(自分のPCからだけ接続できる設定)
- データベース名 / ユーザー名 / パスワード: すべて `taskboard`(自分のPC内だけで使う開発用の値)
- データの保存先: Docker のボリューム `taskboard-db-data`(コンテナを止めたり削除したりしてもデータは残る)
- テーブル: Spring Boot(JPA)がプログラムの内容に合わせて自動で作成・更新する
- 保存するデータ:
  - タスク(内容・状態・期限・優先度・カテゴリ・色・手動の並び位置)
  - カラムごとの並び順の設定
- API:

| 操作 | メソッド | URL | 状況 |
|---|---|---|---|
| タスク一覧の取得(検索・並び替え) | GET | `/api/tasks` | 実装済み |
| タスク1件の取得 | GET | `/api/tasks/{id}` | 実装済み |
| タスクの追加 | POST | `/api/tasks` | 実装済み |
| タスクの更新(編集・移動) | PUT | `/api/tasks/{id}` | 実装済み |
| タスクの削除 | DELETE | `/api/tasks/{id}` | 実装済み |
| タスクの移動(ドラッグ&ドロップ・上へ/下へ) | PUT | `/api/tasks/{id}/position` | 実装済み |
| カラムの並び順の取得 | GET | `/api/columns/{状態}/sort` | 実装済み |
| カラムの並び順の変更 | PUT | `/api/columns/{状態}/sort` | 実装済み |

#### タスク一覧の取得 `GET /api/tasks`
クエリパラメータ(すべて省略できる。複数指定したときは「かつ」で絞り込む):

| 名前 | 内容 | 指定できる値 |
|---|---|---|
| `status` | 状態 | `TODO`(未着手)/ `IN_PROGRESS`(進行中)/ `DONE`(完了) |
| `priority` | 優先度 | `HIGH`(高)/ `MEDIUM`(中)/ `LOW`(低) |
| `category` | カテゴリ(完全一致) | 任意の文字 |
| `keyword` | 内容の部分一致(大文字・小文字は区別しない) | 任意の文字 |
| `sort` | 並び順(省略時は `MANUAL`) | `MANUAL`(手動順)/ `DUE_DATE`(期限が近い順)/ `PRIORITY`(優先度が高い順)/ `CATEGORY`(カテゴリ名順) |

- 期限なし・カテゴリなしのカードは末尾に並ぶ。同じ順位のときは手動の並び位置の順になる。
- 指定できない値を渡したときは `400`、`/api/tasks/{id}` で存在しない id を渡したときは `404` を返す。
- 例: `GET /api/tasks?status=TODO&priority=HIGH&sort=DUE_DATE`

返ってくる JSON(1件分):
```json
{
  "id": 1,
  "title": "週次レポートの資料を作成する",
  "status": "TODO",
  "dueDate": "2026-10-05",
  "priority": "HIGH",
  "category": "仕事",
  "color": "YELLOW",
  "sortOrder": 1,
  "createdAt": "2026-09-27T06:41:06.807512Z"
}
```
- `dueDate` と `category` は未設定のとき `null`。
- `color` の値: `WHITE`(白)/ `YELLOW`(黄)/ `GREEN`(緑)/ `BLUE`(青)/ `PINK`(ピンク)/ `ORANGE`(オレンジ)。画面では色名を文字でも表示する。

#### タスクの追加・更新・削除
追加(`POST /api/tasks`)と更新(`PUT /api/tasks/{id}`)は、同じ形の JSON を送る:
```json
{
  "title": "レポート提出",
  "status": "IN_PROGRESS",
  "dueDate": "2026-12-31",
  "priority": "HIGH",
  "category": "仕事",
  "color": "PINK"
}
```

| 項目 | 追加(POST) | 更新(PUT) | 入力チェック |
|---|---|---|---|
| `title` | 必須 | 必須 | 空白だけは不可。200文字以内。前後の空白は取り除く |
| `status` | 省略時 `TODO` | 必須 | `TODO` / `IN_PROGRESS` / `DONE` |
| `dueDate` | 省略可 | 省略すると期限なしになる | `2026-12-31` の形式 |
| `priority` | 省略時 `MEDIUM` | 必須 | `HIGH` / `MEDIUM` / `LOW` |
| `category` | 省略可 | 省略・空文字だとカテゴリなしになる | 50文字以内。前後の空白は取り除く |
| `color` | 省略時 `WHITE` | 必須 | 色の値は上記のとおり |

- 追加すると `201` と、追加したタスクの JSON を返す(`Location` に `/api/tasks/{id}` が付く)。そのカラムの末尾に並ぶ。
- 更新は全項目の置き換え。成功すると `200` と更新後の JSON を返す。`status` を変えたときは、移動先のカラムの末尾に移る。`status` が同じなら並び位置は変わらない。
- 削除すると `204`(本文なし)を返す。
- 存在しない id は `404`。入力が正しくないとき(必須項目なし・長すぎる・選択肢にない値・日付の形式違い・JSON が壊れているなど)は `400`。
- エラーのときの JSON: `{"message": "入力内容に誤りがあります", "errors": [{"field": "title", "message": "内容を入力してください"}]}`(`errors` は入力チェックのときだけ中身が入る)

#### タスクの移動 `PUT /api/tasks/{id}/position`
ドラッグ&ドロップや「上へ」「下へ」ボタンで、カードを好きな列・好きな位置に移すための API。
- 送る JSON: `{"status": "DONE", "index": 1}`
  - `status`: 移動先の列(`TODO` / `IN_PROGRESS` / `DONE`)。必須
  - `index`: 移動先の列の「手動の並び順」の中での位置。0 が先頭。必須で、0 以上。列の件数より大きいときは末尾に入る
- 移動先の列(と、別の列から来たときは元の列)の並び位置(`sortOrder`)を 1 から振り直す。
- 成功すると `200` と、移動後のタスクの JSON を返す。存在しない id は `404`、入力が正しくないときは `400`。
- 画面での扱い:
  - 並び順が「手動」の列では、落とした位置に入る。「上へ」「下へ」ボタンも、手動の列にだけ表示する。
  - 手動以外(期限順など)の列に落としたときは、列だけ移り、表示される位置はその列の並び順に従う(手動の並びでは末尾に入れる)。
  - 手動以外の列の中で落としても、並び替えはしない(並び順を「手動」にするよう画面で案内する)。

#### カラムごとの並び順の取得・変更
画面で選んだ並び順を、カラム(状態)ごとにサーバーへ保存し、開き直したときに復元するための API。

- 取得: `GET /api/columns/{状態}/sort` → `{"status": "TODO", "sort": "DUE_DATE"}`
- 変更: `PUT /api/columns/{状態}/sort` に `{"sort": "PRIORITY"}` を送る → 保存した結果を同じ形で返す(`200`)
- `{状態}` は `TODO` / `IN_PROGRESS` / `DONE`。`sort` は `MANUAL` / `DUE_DATE` / `PRIORITY` / `CATEGORY`。
- まだ一度も選んでいないカラムは `MANUAL`(手動順)を返す(取得しただけでは何も保存しない)。
- 状態や `sort` が正しくない、`sort` がない、JSON が壊れているときは `400`(エラーの JSON はタスクの API と同じ形)。
- 保存先は `column_sorts` テーブル(カラムごとに1行)。サーバーを再起動しても残る。
- 画面は、ここで取得した `sort` を `GET /api/tasks?status=…&sort=…` に渡して一覧を表示する(タスク一覧の API は、渡された `sort` をそのまま使う)。

### 実行環境・起動方法

**最初に(共通): データベースを起動する**
1. Docker Desktop を起動する
2. `taskboard` フォルダで `docker compose up -d` を実行する(PostgreSQL が起動する)
   - 一度起動すれば、Docker Desktop が動いている間は自動で起動したままになる

**開発中(画面を作りながら確認するとき)**
1. `taskboard` フォルダで `mvnw spring-boot:run` を実行して Spring Boot を起動する
2. 別の画面で `taskboard/frontend` フォルダに移動し、`npm run dev` を実行して React の開発サーバーを起動する
3. ブラウザで `http://localhost:5173/tasksboard.html` を開く(ファイルを保存するとすぐ画面に反映される)

**完成後(ふだん使うとき)**
1. `taskboard/frontend` フォルダで `npm run build` を実行する(画面を変更したときだけ必要)
2. `taskboard` フォルダで `mvnw spring-boot:run` を実行する
3. ブラウザで `http://localhost:8080/tasksboard.html` を開く

終了するときは、それぞれを起動した画面で `Ctrl + C` を押す。
データベースを止めたいときは、`taskboard` フォルダで `docker compose stop` を実行する(データは消えない)。

**動作確認用のテストデータを入れたいとき**
- `taskboard` フォルダで `mvnw spring-boot:run "-Dspring-boot.run.profiles=seed"` を実行して起動する。
- `tasks` テーブルを**空にしてから**テストデータ(13件)を入れ直す。今までのデータは消えるので、本当に使うデータが入っているときは実行しない。
- 通常の起動(`profiles=seed` なし)では、データには一切触らない。
- テストデータの中身: `src/main/resources/db/seed/test-data.sql`

※ `npm run build` で作られるファイル(`src/main/resources/static/`)はgitにはコミットしない。
