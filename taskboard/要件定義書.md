# トレロ風タスク管理アプリ 要件定義書

## 概要
シンプルなトレロ風タスク管理アプリ。個人利用を想定する。
自分のPCで Spring Boot のサーバーを起動し、ブラウザから使う。

## 背景・方針
機能は必要なものに絞る。既存の高機能版とは別物として、基本機能(カードの追加・削除・移動)に加え、期限・優先度・カテゴリの設定、並び替え、カードの色設定までを実装する。

## 利用者像
視力の弱いユーザーでも使いやすいよう、大きめの文字サイズ・高コントラストな配色をデフォルトで採用する(アクセシビリティを最初から考慮する)。
期限切れ・優先度・カードの色などは**色だけに頼らず、必ず文字でも表示する**。

## 機能要件(スコープ内)
1. 固定3カラム: 「未着手」「進行中」「完了」
2. タスクカードの追加(テキスト入力)
3. タスクカードの削除
4. タスクカードをドラッグ&ドロップでカラム間移動
5. ブラウザを閉じてもデータが残るよう、データベース(Docker で動かす PostgreSQL)に保存
6. 大きめの文字サイズ・高コントラストな配色をデフォルトのスタイルとする
7. カードの編集: 追加後のカードの内容・期限・優先度・カテゴリ・色を編集画面で変更できる
8. 期限の設定: カードごとに日付を指定できる(未設定も可)
   - 期限切れ・今日が期限のカードは「期限切れ」「今日まで」と文字で表示する
9. 優先度の設定: 「高」「中」「低」の3段階から選ぶ。カード上に文字ラベルで表示する
10. カテゴリの設定: カードごとに自由に文字で入力できる(未設定も可)。カード上に文字で表示する
11. カードの色設定: 用意した数色から選ぶ
    - 選択肢には色名も文字で表示する
    - どの色でもカードの文字がはっきり読めるコントラストを保つ
12. 並び替え: 各カラムの上部で、カラムごとに個別に並び順を選べる
    - 選択肢: 「手動(ドラッグ順)」「期限が近い順」「優先度が高い順」「カテゴリ順(名前順)」
    - 期限なし・カテゴリなしのカードは末尾に表示する
    - 選んだ並び順もサーバーに保存する

## 非機能要件
- ユーザー認証なし
- 複数人での共有なし(自分のPC上でのみ利用)
- レスポンシブ対応は必須としない(PCブラウザでの利用を想定)

## 今回のスコープ外(将来の拡張候補)
テーマ切替、文字サイズ切替、カラムの追加・編集・削除、カテゴリ一覧の管理(追加・編集・削除)、ログイン機能、インターネット上への公開 など。
必要になれば既存の高機能版を参考にできる。

## 画面構成(簡易)
- ヘッダー(タイトル)
- 3カラムのボード(各カラムの上部に並び替えメニュー)
- カード編集画面(ダイアログ): 内容・期限・優先度・カテゴリ・色を設定

## 技術スタック

### 全体の構成図
```
[ブラウザ]
  React で作った画面(フロントエンド / 入口は tasksboard.html)
        │  fetch で JSON をやり取り(REST API)
        ▼
[Spring Boot サーバー](バックエンド / http://localhost:8080)
  Controller(API の窓口)→ Service(処理)→ Repository(DB操作)
        │  Spring Data JPA(localhost:5432 に接続)
        ▼
[PostgreSQL データベース](Docker のコンテナ「taskboard-db」で動く)
  データは Docker のボリューム「taskboard-db-data」に保存
```

開発中と完成後で、画面の配信元が変わる。
- **開発中**: React の開発サーバー(Vite / `http://localhost:5173`)が画面を配信し、`/api` へのアクセスを Spring Boot(8080)に中継する
- **完成後**: `npm run build` で React の画面を HTML/JS/CSS に変換して `src/main/resources/static/` に出力し、Spring Boot が画面も API もまとめて配信する

### フロントエンド
- ライブラリ: React 19
- 開発ツール: Vite 8(開発サーバーとビルド)/ Node.js・npm
- 言語: JavaScript(JSX)。TypeScript は使わない
- 置き場所: `taskboard/frontend/`
- 入口の HTML: `frontend/tasksboard.html`(`index.html` ではなくこの名前を使う)
- 部品(コンポーネント)構成:

```
App(アプリ全体)
 ├─ Header(タイトル)
 ├─ Board(ボード)
 │   └─ Column × 3(未着手・進行中・完了)
 │       ├─ SortMenu(並び替えメニュー)
 │       └─ TaskCard × 件数分
 └─ EditDialog(カード編集画面)
```

- サーバーとの通信: fetch で REST API を呼ぶ
- スタイル: CSS(大きめの文字サイズ・高コントラストな配色をデフォルトで組み込む)
- 対応ブラウザ: 主要モダンブラウザ(Chrome/Edge等)を想定

### バックエンド
- 言語: Java 21(Microsoft Build of OpenJDK)
- フレームワーク: Spring Boot 4.1
  - Spring Web … REST API と画面ファイルの配信
  - Spring Data JPA … データベース操作
- ビルドツール: Maven(プロジェクト同梱の Maven Wrapper `mvnw` を使うため、Maven 本体のインストールは不要)
- 接続設定: `src/main/resources/application.properties`(接続先・ユーザー名・パスワードは環境変数 `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` で上書きできる)

### データベース
- 種類: PostgreSQL 18
- 動かし方: Docker Desktop 上のコンテナとして動かす(設定ファイルは `taskboard/compose.yaml`)
- コンテナ名: `taskboard-db`
- 接続先: `localhost:5432`(自分のPCからだけ接続できる設定)
- データベース名 / ユーザー名 / パスワード: すべて `taskboard`(自分のPC内だけで使う開発用の値)
- データの保存先: Docker のボリューム `taskboard-db-data`(コンテナを止めたり削除したりしてもデータは残る)
- テーブル: Spring Boot(JPA)がプログラムの内容に合わせて自動で作成・更新する
- 保存するデータ:
  - タスク(内容・状態・期限・優先度・カテゴリ・色・手動の並び位置)
  - カラムごとの並び順の設定
- API(予定):

| 操作 | メソッド | URL |
|---|---|---|
| タスク一覧の取得 | GET | `/api/tasks` |
| タスクの追加 | POST | `/api/tasks` |
| タスクの更新(編集・移動) | PUT | `/api/tasks/{id}` |
| タスクの削除 | DELETE | `/api/tasks/{id}` |
| カラムの並び順の取得 | GET | `/api/columns/{状態}/sort` |
| カラムの並び順の変更 | PUT | `/api/columns/{状態}/sort` |

### 実行環境・起動方法

**最初に(共通): データベースを起動する**
1. Docker Desktop を起動する
2. `taskboard` フォルダで `docker compose up -d` を実行する(PostgreSQL が起動する)
   - 一度起動すれば、Docker Desktop が動いている間は自動で起動したままになる

**開発中(画面を作りながら確認するとき)**
1. `taskboard` フォルダで `mvnw spring-boot:run` を実行して Spring Boot を起動する
2. 別の画面で `taskboard/frontend` フォルダに移動し、`npm run dev` を実行して React の開発サーバーを起動する
3. ブラウザで `http://localhost:5173/tasksboard.html` を開く(ファイルを保存するとすぐ画面に反映される)

**完成後(ふだん使うとき)**
1. `taskboard/frontend` フォルダで `npm run build` を実行する(画面を変更したときだけ必要)
2. `taskboard` フォルダで `mvnw spring-boot:run` を実行する
3. ブラウザで `http://localhost:8080/tasksboard.html` を開く

終了するときは、それぞれを起動した画面で `Ctrl + C` を押す。
データベースを止めたいときは、`taskboard` フォルダで `docker compose stop` を実行する(データは消えない)。

※ `npm run build` で作られるファイル(`src/main/resources/static/`)はgitにはコミットしない。
